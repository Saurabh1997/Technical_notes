----------------------type inference in typescript---------------------------------------------
	is the ability of  a compiler to identify the data type of the variable or function value without explicit type annotations. 

---------------------------------------------explicit and implicit assigning--------------------------------------------------------- 
let firstName: string = 'saurabh' // explicit - writing out the type

let firstName = "saurabh" // typescript will guess the type based on assigned value. 
Having typescript guess the type of a value is called infer. Implicit assignment forces typescript to infer. 

for explicit, it will throw error for mismatching. but for implicit, it won't throw error. 

------------------------------------------------------------TYPESCRIPT SPECIAL TYPES---------------------------------------------------------------------------
any - disables type checking. but it won't provide any type checking. SHOULD BE AVOIDED AT ANY COST. 
unknown - similar to any but safer. it will prevent unknown types from being used. will have to do typeof/instanceof check before performing any operation. 
never - let x : never = true // throws error whenever it is defined. 
			THIS TYPE REPRESENTS A VALUE THAT WILL NEVER OCCUR. used in scenarios where a function never returns anything.

-----------------------------------------------------TYPECASTING with AS/<> OR TYPESCRIPT CASTING------------------------------------------------------------------
CASTING - IS OVERRIDING THE EXISTING TYPE. 
TO EXPLICITLY TELL THE TYPESCRIPT COMPILER THE SPECIFIC TYPE OF A VALUE EVEN WHEN COMPILER'S AUTOMATIC TYPE INFERENCE MIGHT NOT BE ACCURATE. IT IS COMPILE TIME CONSTRUCT 
	------ when to use 
		- working with dynamic data - when any data is coming from external sources - API. 
		- When we have more knowledge of data than what compiler can infer. 
		- interacting with JS legacy code. 
	
	------ HOW TO USE -----
		- let someString: any = "Hello"
		- let len : number = (someString as string).length
	
		--- OLDER SYNTAX <>
			let x : unknown = "hello"  
			console.log((<string>x).length)  or console.log((x as string).length); // this won't change type of data within variable. 
			
SNIPPETS : 
		let x: unknown = 4;
		console.log((x as string).length); 
			OUTPUT - ------------ // prints undefined since numbers don't have a length
		
------------------------------------------------------------
		TYPESCRIPT WILL ATTEMPT TO TYPECHECK CASTS TO PREVENT CASTS THAT DON'T SEEM CORRECT. 
		
		console.log((4 as string).length); 
		
		// Error: Conversion of type 'number' to type 'string' may be a mistake because neither type sufficiently overlaps with the other. If this was intentional, convert the expression to 'unknown' first.
---------------------------------------------------------------
let x: unknown = 'hello';
console.log((<string>x).length);  // THIS WILL WORK. 


---------------------------------------------------FORCE CASTING-------------------------------------------------------------------------
// to override type errors, WE CAN TYPE CAST TO UNKNOWN AND THEN TRY TO FORCE CAST IT TO ANOTHER TYPE THAT WE WANT. 

let x = 'hello';
console.log(((x as unknown) as number).length); // x is not actually a number so this will return undefined

---------------------------GENERICS - FOR TYPECASTING A FUNCTION --- dynamically typecast.. work with any data type----------------------------------
Used for creating a type variable which can be used for creating classes, functions & types aliases that we don't need to explicitly use 
- can write reusable code. 

	- Generics When working with functions can help make more generalized which can accurately represent the data types it requires and returns. 
	

		function getArray(items : any[]): any[] {
		return new Array().concat(items)
		}

		let numArray = getArray([1,2,3,4,5])
		let strArray = getArray(["hello","snsns"]) 	// IT WILL ALSO ACCEPT THIS AS WE ARE ACCEPTING ANY ARRAY. 

		strArray.push(6,7) // SAME GOES FOR THIS.

		FOR TYPECASTING,  

		function getArray<T>(items : T[]): T[] {
		return new Array().concat(items)
		}

		let numArray = getArray<number>([1,2,3,4,5]) // THIS WILL PASS NUMBER AS T AND WILL MAINTAIN THIS DATATYPE FOR NUMARRAY. 
		let strArray = getArray<string>(["hello","snsns"]) 	// THIS WILL PASS STRING AS T AND WILL MAINTAIN THIS DATATYPE FOR strArray.

		strArray.push(6,7) // WILL GIVE ERROR AS WE ARE PASSING STRING AS THE TYPECASTING VARIABLE.

----------------------------------------------------------------CLASSES-------------------------------------------------------------------------------------
Typescript adds types and visibility modifiers to JS classes. 
Class members can be given additional visibility modifiers - 
	public (default) - allows access to class member from anywhere.
	private - only allows access from within the class 
	protected - allows access from within the class and the classes which inherit it. 

---------------------------------------------------------------UTILITY TYPES----------------------------------------------------------------------------------
- predefined generic types - that provides transformation and operations on existing types - allowing for creation of new types, based on modification and extraction of properties and reusing existing types. 
Partial - changes all properties in an object to be optional.
Required - changes all properties to be required. 
Record - shortcut to defining an object type with specific jet type and value type. 
Omit - removes keys from an object type. 
Pick - removes all but specified keys from an object. 
Exclude - removes types from a union. 
ReturnType - extracts return type of a function. 
Parameter - extracts the parameter types of function as an array.

------------------------Pick--------------------------------
allows us to pick new type by selecting a set of properties from an existing type. 

interface User {
	id:number;
	name: string;
	email: string;
	createdAt: Date;
	}
	
type UserProfile = Pick<User, 'name' | 'email'>    // only pick name and email types...

const displayUserProfile = (UserDet : UserProfile) => {}

------------------------Partial----------------------------
makes all the properties in a type optional. 

type UserProfile = Pick<User, 'name' | 'email'> 

const displayUserProfile = (UserDet : Partial<UserProfile>) => {}  // all properties are now optional.

---------------------Record and Map--------------------
cleaner way to give types to objects. 

interface User {
	name: string;
	age: number
	}

Instead of doing , type Users: { [key: String]: User } = {
						"userid" : {
							name:"saurbah",
							age: 18
							}
					}
 can use Record to do this, 
			type Users: Record<String, User>  = {
						"userid" : {
							name:"saurbah",
							age: 18
							}
					}
Map can give fancier way to deal with objects. 
			const usersMap = new Map<string, Users>()
	UsersMap.set("userId", {name:"Gaurav", age:20})
