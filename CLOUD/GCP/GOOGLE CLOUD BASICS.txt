-----------------------------------------DATABASES - SQL/NOSQL------------------------------------------------------------------
-- Two options for SQL - CLOUD SQL and CLOUD SPANNER 

- CLOUD SQL - If app is running for a single region only. 99.99% availability no availability in other regions. don't expect data to grow beyong 64 TB. MySQL, PostgresQL, MariaDB are supported here. 

- CLOUD SPANNER - If we want Global Database - If we want horizontal scalability and 99.999% availability and unlimited storage. WITH STRONG TRANSACTION AND STRONG CONSISTENCY. USED FOR BANKING AND FINANCIALS 

--- NOSQL DB - When we want to use for social media with high availability apps  - FIRESTORE & BIGTABLE  

- FIRESTORE (DATASTORE) - for normal noSQL data storing - transactional data storing.

- BIGTABLE - for large amount of streaming data, time series data retrieving on single key. FOR HUGE VOLUMES OF DATA.

---------------------------------------STORAGE--------------------------------------------------------------
3 TYPES OF STORAGE - Block, File and Objects. 

- BLOCK STORAGE - Single block storage is attached to 1 VM. 1 HARD DISK IS ATTACHED TO ONE VM only. To 1 VM, we can have multiple HDS. Same disk can't be attached to multiple VMs. 
		In Google compute, if we create any VM, it'll be created using PERSISTENT DISK SERVICE. if want to create file share, we will go for FILE STORE.  

- FILE STORAGE - File store - File storage shared between multiple VMs - can be physically attached to VM.  BLOCK STORAGE AND FILE STORAGE CAN HAVE DIRECT CONNECT TO VMs.

- OBJECT STORAGE - also known as CLOUD STORAGE (Similar to S3 in aws, blob storage in azure) - for uploading downloading files of Users from client side. We have REST APIs to upload  (key - file name, value - content of file pair) and download. In a bucket kind of thing. ALSO USED TO HOST STATIC FILES OF REACT BUILD. can be expose it as a website.
