components of kubternetes - 
POD - smallest unit. abstraction layer over on top of container. pod is meant to run one container/one application. 
	EACH POD HAS A UNIQUE IP ADDRESS. pod components when restarted 0r died and a fresh pod is backed up,then they have a different unique ip address. 
	
SERVICE - TAKES CARE OF STATIC/PERMANENT IP ADDRESS THAT CAN BE ATTACHED TO each pod so that we don't have to handle ip addresses 
changing everytime a new pod starts.  

INGRESS - route traffic into the cluster. EXTERNAL SERVICE WHICH HAS ACCESS TO THE INTERNAL SERVICE THROUGH BROWSER. INSTEAD OF SERVICE, 
REQUEST GOES TO INGRESS FIRST AND THEN TO THE SERVICE
ingress controller - kind of UI/dashboard to access services through GUI to check health, status of the service. 
external ingress controller includes istio, eks. 

pods communicate with each other via services. 
 
 mongodb service - db url usually usually in built application image then push it to repo and pull from repo to pod. 
 this becomes tedious so we use ConfigMap - external configuration of the application 
 for putting USERNAME, PASSWORD  - WE USE SECRET - stored in base64. to store certis,

DATA STORAGE - if pod gets restarted, data will be gone. so we use VOLUME componnent of kubernetes.
VOLUMES -- it attaches physical storage or hdd either on local machine where pod is running or remote, outside k8s cluster.. cloud storage
K8s doesn't manage data persistence. 

stateful Deployment -  to reduce the downtime of pod restarting, we replicate everything. another container would be running on another node 
which will be connected to the same service. Service has 2 functionalities - permanent IP and load balancer - balance between pod to handle workload

TO CREATE REPLICA - we won't create another pod. we will define blueprint and specify how many replicas to create of that pod
this blueprint is called as DEPLOYMENT (component of kubernetes)  
we will be creating deployments, not pod where we can scale up pod replicas. DEPLOYMENT is another abstraction layer over pods and 
pods are layer above container. 

STATEFULL SET
we can't replicate db using deployment as db has state as there can be data inconsistency. if we have clones of db, they would have to access same shared db. 
will need mechanism to manage which pods are reading/ writing to that db. this mechanism of replicating is STATEFULL SET. 
for stateful apps or databases for mongoDB, other DBs. statefull set would take care of replicating pods amd scaling them up and making sure that all db reads 
and writes are synchronized.  

Deploying statefulSet isn't easy --- so good practice to host DBs outside of K8s cluster and just have stateless deployments in k8s cluster.

----LIFECYLE OF POD 
starts from pending phase, moving through running phase and then either succeeded or Failed phase depending upon whether any container in pod terminated
in failure. 
Within a pod, kubelet is able to restart containers to handle faults. kubernetes tracks different containers & its states and determines what actions to take 
to make pod healthy.
Pods are only scheduled once in their lifetime. Pods are created and assigned a uuid & scheduled to node. If a node dies, pod scheduled to that node is scheduled
for deletion. 
Kubernetes uses high-level abstraction called "Controller", that handles work of managing disposable pod instances. 
Pod with volume is also destroyed.
