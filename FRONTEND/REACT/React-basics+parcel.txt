 static getDerivedStateFromProps(props, state) {
    // Any time the current user changes,
    // Reset any parts of state that are tied to that user.

    if (props.userID !== state.prevUserID) {

        prevUserID: props.userID,

    return null;
  }

-----------------------------------------SYNTHETIC EVENTS---------------------------------------------------------
Synthtic Events are nothing but a wrapper created around NORMAL NATIVE BROWSERS ORIGINAL EVENTS (on input change, on button click) in order to avoid creating multiple browser methods for multiple browsers - creating common names for all browsers. 

- SYNTHETIC EVENTS ARE LIKE AN ABSTRACTION LAYER THAT REACT PROVIDES OVER NATIVE ORIGINAL BROWSER EVENTS TO EXECUTE THEM IN CONSITENTLY AND CROSS BROWSER COMPATIBLE MANNER. THEY ARE JS OBJECTS WHICH WRAP NATIVE EVENTS. react Also provides event pooling for better performance AND IT USES A MECHANISM CALLED EVENT DELEGATION TO IMPROVE PERFORMANCE. 

- WHEN WE USE REACT ONCHANGE, ONCLICK, WE PASS A FUNCTION TO THIS EVENT HANDLERS N IT TYPICALLY CREATES A SYNTHETIC EVENT OBJECT N PASSES IT TO EVENT HANDLER FUNCTION. 
	example - IF WE PASS HANDLECLICK FUNCTION TO ONCLICK HANDLER, HANDLECLICK WILL BE CALLED WITH SYNTHETIC EVENT OBJECT AS ITS ARGUMENT. 
		can access various properties and methods available on synthetic event object such as - 
			event.target
			event.type 
			event.preventDefault() , event.stopPropagation(). 
		NOTE: event Object (e) that we get as a parameter in handler function is synthetic event object 	
			
	benefit of this is - cross browser compatibility, 
		- Event pooling - reduces memory consumption & improve performance by - after event handler function is done executing, its returned to the pool & can be used for another event. 
		- Asynchronous Event handling - react batches multiple events together & updates component state in a single rerender.

------------------------------RECONCILIATION AND DIFFING ALGORITHM--------------------------------------------------------------------------
2 process happen in react - reconciliation - to compute which parts of tree are changed.
rendering - renderer uses the information returned by reconciler to actually update the rendered app. 
Both happen in seperate process. THIS SEPERATION MEANS SAME RECONCILER CAN BE USED BY REACT AND REACT NATIVE AND CAN USE DIFFERENT RENDERERS. 

React uses RECONCILIATION algorithm (also known as React FIBER - REACT 16)- 
Reconciliation is A PROCESS OF ensuring HOW VIRTUAL DOM WILL BE REFLECTED INTO THE ACTUAL DOM. React compares new virtual DOM with the previous DOM and determines min no of operations needed to make the update in actual dom.  

React creates virtual dom. virtual dom is representation of actual dom (object representation of actual dom). 
Virtual dom is nothing but a normal js object (React element). 
Whatever changes we are doing that are reflected in the virtual dom.. For example - if we filter the list when clicked on button
	
DIFF ALGORITHM - diffing is core part of reconciliation. comparison process is called diffing. 
it finds the difference between previous and new virtual dom to identify the differences then updates that particular dom. it finds the difference between two objects which is faster than finding difference between two HTML elements. 
React implements a heuristic O(n) algorithm based on few assumptions: 
		1.  2 elements of diff type will have 2 diff tree. 
		2. 	Developer can tell which child element maybe stable due to different key prop. 
	When comparing elements of same type, React will only update the attributes which are changed. 	
	Heuristic algo is used to efficiently determine min set of changes required to update the DOM. 
Note: updation at end of node will hve good performance over updation at beginning.. in a list. but react works with keys (different key)
OBSERVATION : Using indexes as key can cause issues with states if we are doing reordering.. If key is an index, moving an item changes the key only.. 
NOTE: Rerender doesn't mean component will unmount and mount again.. it will only apply the differences following the diffing algorthm. 

---------------------------------KEYS IN LOOPING ARRAY-------------------------------------------------
Keys should be stable, predicatable and not Using Math.random() as it will cause many instances unneccessary render AND CAN CAUSE PERFORMANCE DEGRADATION AND LOST STATE in child components.. 

WHY KEY IS IMPORTANT : to uniquely identify an element within the list of elements.. its used to prevent rerendering of list of elements. so that react will know which key number of element to update.. 
NOTE:   	Never use index AS A KEY. its an anti-pattern. coz index might cause issue with rerendering when index is reordered. IF WE ADD OR DELETE ELEMENT OR REORDER THE ELEMENT, INDEX WILL CHANGE AS PER .MAP DYNAMICALLY WHICH CAN CAUSE EXTRA RERENDERING.

------------------------------------------------------------TRANSITIONS IN REACT 18---------------------------------------------------------------------
 - Transistions lets us mark certain state updates as non-urgent without compromising user experience - to prevent blocking UI. 
 - can wrap state updates that can be delayed without delaying User experience inside startTransition. 
 - REACT PRIORITIZES URGENT UPDATES (USER INPUTS OR ANIMATIONS) OVER TRANSITIONS. If there is an urgent update while transition is in progress, React will pause the transition, handle the update and then can resume the transition. 

--- can be used where ---
- CAN BE USED IN SCENARIOS WHERE - THERE IS A SEARCH INPUT WHICH HAS TO UPDATE ITS VALUE AS SOON AS WE TYPE ANYTHIING AND THERE ARE 2000 SEARCH RESULTS WE WANT TO RENDER IN DROPDOWN BASED ON THE ITEM WE ARE SEARCHING IN INPUT. SO SETSTATE FOR INPUT STATE CAN BE URGENT AS WE WANT CLIENT TO SEE WHAT HE IS TYPING.. BUT SEARCH RESULTS IN DROPDOWN CAN BE DELAYED - SO THIS SETSTATE FOR SEARCH RESULTS CAN BE MARKED AS NON-URGENT/LOW PRIORTY AND CAN BE INSIDE START TRANSITION BLOCK. 
- Updating data that doesn't need updating immediately on the screen - search results, filtering large dataset.
 - Performing complex calculations or data transformations which can freeze UI. 
 
 - FOR EXAMPLE - 
		
	import { startTransition } from "react"
	
const handleChange = () => {
		setStateForInput(e.target.value)
		startTransition(() => {
		// DO STATE UPDATES HERE. 
		setStateForSearchResults(listOfLargeDataset)
	})
}

--------- NOTE : ONE THING TO KEEP IN MIND IS TO BE CAREFUL WHILE USING TRANSITIONS AS IT WILL INCREASE THE NUMBER OF RENDERS. REACT DOES BATCHING OF STATE UPDATES AND WILL RERENDER EVERYTHING AT ONCE AFTER UPDATING THE STATE - WHICH WILL ALL BE IN SAME CYCLE - OR ALL STATE UPDATES IN SAME RENDER... BUT IF WE USE TRANSITIONS, IT WILL FIRST DO STATE UPDATES FOR HIGH PRIORITY STATES, AND THEN CAUSE RERENDER.. AND THEN WILL DO STATE UPDATES FOR LOW PRIORITY AND THEN AGAIN RERENDER FOR IT. SO WE ARE INCREASING RENDER CYCLES AND CAUSING ONE MORE SET OF RENDER.

	--- IF WE HAVE LOT OF SMALL STATE UPDATES WHICH CAN BE DONE IN  SINGLE BATCHING, WE DON'T HAVE TO USE TRANSTIONS. IF THE SETTING DATASET IN STATE IS LARGE, WHICH MAY CAUSE SOME ISSUE OF LAGGING WHILE RENDERING AND MIGHT BLOCK USER INPUTS, SO WE CAN USE TRANSITIONS HERE.
