Graphql -

A query language for api which gives client a power to ask for what exactly they need. 
its a layer between database and the client side queries. 
benefits of Graphql  - 

1. Prevents over fetching - 
		we define the structure of data that we want through a query. We define the structure pf data that we want. 
				query {
				products {
				name 
				image
				}}	
	With Rest API, we get all data ... even if we don't want. 
	
2. Prevents under fetching - 
		Suppose we have to fetch data as per the category.. then two api calls would be required.
			1. first api call to get category id.. and 2. second api to get the products in that category id. 
			THIS PROBLEM CAN BE CALLED AS UNDER FETCHING AS WE ARE NOT ABLE TO FETCH ALL DATA IN SINGLE CALL. 
		query {
		category(id:1) {
			name 
			products {
			image
			name }}}

GRAPHQL SERVERS - to create a graphql , we need two things --- TYPE DEFINITIONS AND RESOLVERS. 

---TYPE DEFINITIONS - describes how the data is going to be when exposing anything - post, likes and review (example) SCHEMA - way that our query is going to look, data is going to look, the way our mutations are going to look. 
	and how our data is linked to each other. 
	TypeDef schema looks similar to the DB schema. 
	
	5 basic scalar builtin types in graphql - int, float, string, boolean, ID 
	ID is key graphql uses for data objects. they are serialized string. 
	Can make our own types using this types. 
	
	export typeDef = `#graphql 
	type User {
		user_id: ID!,     ! - denotes it is required. 
		name: string!, 
		activity_assigned: [string!]! // [string] - denotes array of string. string!] - means string inside array cannot be	null.		
	}
	
	type activity {
		id: ID!,
		activity_name: string!,	
	}
	
	type Query {
		users: [User] // this will specify to get list of users. also specifies that this is single entry point to get Users
		activities: [Activity]				// 
	}
	
	`

	// type Query is needed to define the entry point to the graph and specify the return types of those entry points. 
	// single entry point will only get list of Users and not link to single User or any other entity. so we need to map all entry points. 
	// ABOVE CODE IS FOR GETTING LIST OF USERS AND LIST OF ACTIVITIES AND NOT FOR SINGLE USER/ACTIVITY. 

for e.g :  fruits: [String]

TypeDef is for structuring the graph and we make resolver functions to handle the query based on our schema. 

RESOLVERS -  Resolvers are going to handle the client requests and return the data that client has requested. functions that return the data that conforms(obeys the rule) the way we have defined in the schema.

	GraphQL Query Variables - to fetch all values we are using normal typedefs Query which we have mapped to array of our required entities. But to fetch a single value this won't work we need to use query variables. 
	
	In TypeDefs , 
	
		we will add mapping for single value fetching based on ID (or some other column that we want to fetch from). 
		
		const typeDef = `#graphql
		type User {}
		type Query {
			users: [User] 
			user(id: ID!): User // mentioned id is required and it accepts id as argument.
			}`
		
	In resolver, 
		we write a seperate resolver function to fetch a single value. It accepts 3 arguments
	parent - this is mostly used for accessing related data nested data. 
	args - used to access any query variable. 
	context -  optional - used for supplying context values across all resolvers - such as authentication info. 
	
	const resolver = {
		Query: {
			games(){}
			game(parent , args, context) {   
				console.log(args.id) 
				return db.games.find((review) => review.id === args.id)
			}
		}	
	}

----------------MUTATION---------------------
	Adding and deleting data is done via mutation. 
	
	
1. Deletion of Data---------------------------------	
	In TypeDef, we define - 
	
		type Mutation {
			deleteGame(id: ID!): [Game]   // id is compulsory for executing deletion of game and we also give return type  
											// as array of Game as we want to return updated array of games after deletion.		
		}
		
	In resolver function, 
		Mutation: {
			deleteGame(_, args){
				db.games = games.filter((game) => game.id !==args.id)
				return db.games
			}
		}
		
	and while doing query for the same, we write mutation instead of Query. 
	
	Mutation deleteMutation($id: ID!) {
		deleteGame(id: $id){
			id, title, platform
			}
		}
		// IN VARIABLE WE PASS IN THE ID TO BE DELETED. 

2.Addition of Data--------------------------

In typeDef, we define inputs first as we will have to create an input type which is expected for this mutation. 

input addUserInput {
	name String!,
	age Int!
}	
	
and then we add this input into the Mutation typedef, 

	type Mutation {
		addUserInput(user: addUserInput) : Game  // we are defining user as argument of input type addUserInput.
		}
		
	In RESOLVER FUNCTION ---
	
	Mutation : {
		addUserInput(__, args) => {
			let user = {
				...args.user,
				id: Math.round(Math.random * 10000)
			}
			db.users.push(user)
			return db.users;
		}
	
	}
	
3. Updating Data-------------------------
	In typeDefs, 
	
	type Mutation {
	updateUser(id: ID!, User:EditUserInput): User	// WE ARE ACCEPTING ID AND ANOTHER OBJECT - EditUserInput	
	}
	
	we define edit User Input as such that we can update anything we want so we don't have to make any input necessary. 
	
	input EditUserInput {
		name: String
		mobile_number: String
		age: Int	
	}
	
	And in Resolvers, to make the mutation typeDef - updateUser 
	
		Mutation : {
			updateUser(__, args) {
				db.users = users.map((u) => {
				if(u.id == args.id) {
					return {...u, args.edits}
					}
					return u
				})
				users.find((u) => u.id === args.id)   	// TO FETCH THE UPDATED RECORD. 
			}
		}
