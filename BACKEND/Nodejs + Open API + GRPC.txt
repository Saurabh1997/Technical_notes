PM2 vs cluster - 

PM2 and cluster are both used to scale nodejs applications across multiple CPU cores. 
1. Management - PM2 provides process manager that provides  lot of features such as application health monitor, log output, restart failed processes. whereas cluster provides basic process management & load balancing.
2. Configuration - PM2 provides lot of configuration via json and js files.. to configure number of processes, usage, whereas cluster just provides basic api to configure worker processes.
3. PM2 is designed to work in production environments & provides 0 downtime deployments & restarts. 
4. PM2 can work with any nodejs application. and is more powerful process manager.

--------------EVENT LOOP IN NODEJS------------------------------
	JS is synchronous, blocking, single-threaded by default. To make async programming possible, it uses libuv. 
	---Code execution in nodejs - 
		We have v8 engine where our JS code will execute and libuv where async methods calling will execute. In V8 engine, we have 2 things - heap and call stack. whatever variable declaration is ther, it will be put into HEAP and whatever methods we are calling will go to call stack (Last in First out). LIBUV USES NATIVE ASYNC METHODS OF OS TO EXECUTE ASYNC METHODS.. if not available it will use thread from its thread pool to not block the main thread. 
	EVENT LOOP ORCHESTRATES THE EXECUTION OF SYNCHRONOUS AND ASYNCHRONOUS CODE IN NODEJS.
	
	Event Loop in nodejs in every iteration of the loop we come across 6 different queues - 
		1. timer queue. // associated with SetTimeout, interval
		2. I/O queue // http calls, fileread calls
		3. checkqueue // setImmediate calls
		4. close queue // handle closing the the callbacks - this 4 are part of LIBUV in nodejs
		microtask queues -- 5. nextTick queue // process.nextTick callbacks
							6. Promise queue // for promise callbacks. 
	
---Execution order ----
	1. Any callback functions in microtask queues is executed - first nextTick queue and then promise queue callbacks. 
	2. All callbacks in timer will be executed. then again step 1.
	3. All callbacks in I/O will be executed. then again step 1 if there are any callbacks in microtask.
	4. All callbacks in checkqueue and then step 1.
	5. All callbacks in close queue and then step 1. 

	
	NOTE: ALWAYS USER WRITTEN SYNCHRONOUS JS CODE WILL TAKE PRIORITY OVER ASYNC CODE AND ONCE CALL STACK IS EMPTY EVENT LOOP WILL COME INTO PICTURE.

-----------------------------STREAMS IN NODEJS-------------------------------------------------------

Stream is an abstract interface for working with streaming data in nodejs. 

4 fundamental stream types in nodejs - 
	1. Writable stream - streams to which data can be written. 
	2. Readable stream - streams from which data can be read.
	3. duplex - streams to which data can be written as well as can be read from. 
	4. transform - duplex streams to which data can be modified and transformed as it is written and read.

------------------------------------------------protobuffs------------------------------------------------
		
	Proto Buffs - protocol buffers - are used by GRPC - Google's language neutral, platform neutral mechanism for serializing data - XML, JSON. - buts its faster, smaller and simpler. 
	PROTOBUFFS - IS A FORMAT TO STORE OR TRANSFER DATA OVER THE NETWORK. it is like compressing the data, zipping it and then sending it and then while receiving, unzipping and then decoding the data. actual data transferred or stored as protobuff is like a hex code.
	
	Protobuffs are where we define our service difinitions & messages. its like a spec file/contract/common interface between client and the server of what to expect from each other. Method , type & result of operation to expect.
	IT SUPPORTS CODE GENERATION FOR variety of programming languages.
	
	to define a protobuf, we HAVE TO DEFINE THE SHAPE/STRUCTURE OF OUR DATA: 
	
	pbufFile.proto:
	
	syntax="proto3";
	
	message Person {			// a message of type Person that can be encoded/decoded/transferred.
		string name=1;			// each field in the message type is assigned a unique field number or a tag number we usually start from 0.  
		int32 age=2;	
	}
	
	// assigning field number does - Efficient encoding - serialization and deserialization based on field number and not on the field variables. including Field // numbers in the serialized data makes it more compact and faster to procress.
	// Field numbers are stable identifiers for the field.. even if we change the order add or remove fields we can decode old serialized data 
	
	service PersonService { // WE  DEFINE OUR OWN SERVICE WHICH TELLS WHAT RPC SERVICES WE ARE EXPOSING TO THE OUTSIDE WORLD.  
		rpc AddPerson(Person) returns Person // this defines that there is RPC method AddPerson 
											// which expects Person type message and will return Person type msg.
		
		rpc GetPersonByName(PersonNameInput) returns Person // this RPC method GetPersonByName expects PersonNameInput as parameter and returns whole Person msg.
	
	}	
	
	message PersonNameInput {   // THIS IS DEFINITION OF THE INPUT REQUIRED IN GetPersonByName RPC. 
		string name=1          
	}
