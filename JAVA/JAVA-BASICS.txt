-----------------------MEMORY---------------------------
Inside JVM, we have memory. 
1. Stack - LIFO - last in first out. local variables and methods are part of stack.  
2. Heap - we store objects. Instance variable and object (reference variable) are part of heap. 
	Calculator classObj = new Calculator; // this is inside main()
	so here classObj will be in stack and will have reference to address. 
	Heap will have address of that reference variable n in that address will have properties(instance variable  n methods) of that class.  
NOTE: STACK IS CONNECTED TO HEAP VIA THE ADDRESS THAT THE REFERENCE VARIABLE POINTS TO. 

Memory in application is called heap memory managed by JVM.  JVM calls out a subroutine (system.gc) to delete all the objects which it can't reach out from the main stack. 
Whenever an object is created, entry is made in the heap and if we assign it as null after use, then it becomes eligible for garbage collection.

-----------------------INTERFACES-------------------------------
WHEN WE HAVE AN ABSTRACT CLASS WITH ONLY ABSTRACT METHODS, WE CAN IMPLEMENT THE SAME USING INTERFACE. HIERARCHY WISE WE IMPLEMENT INTERFACES .

A CLASS CAN EXTEND ANOTHER CLASS AND IMPLEMENT ONE OR MORE INTERFACES. 
a CLASS IMPLEMENTING AN INTERFACE MUST BE PUBLIC. BY DEFAULT METHODS IN INTERFACE ARE ABSTRACT AND PUBLIC. 

	--- WHY VARIABLES ARE FINAL AND STATIC IN INTERFACE. 
--Variables declared in interface are by default final and static. No need to specify final and static. Can access variables directly on the interface name as its static. 
-- We don't have heap memory for interfaces as we can't instantiate/create new object. So we have to have interface variable as STATIC to access it directly on the interface name. 
-- We can only access methods and override this methods and not variables as we are only implementing and not extending. so we only get methods and not variables. so variables are final. 

NOTE: INTERFACE REF VARIABLE WILL DECIDE WHICH METHODS THE OBJ REF VARIABLE CAN CALL AND NOT THE OBJECT THAT ITS REFERING TO. 

EXAMPLE :

interface A {

}
class C implements A, B

class implements A, B {

	a.m2() // not allowed as B has the m2 method and not A.

------------------------------------------------------MULTITHREADING--------------------------------------------
In the same process, same task, we can divide everything into multiple subprocess and tasks into smallest unit to execute them together with the help of threads. This is called multi-threading. Thread is a light weight process in java which runs concurrently with other threads. Threads are independent of each other & can run simultaneously. 
Threads can be more used for doing CPU intensive tasks or concurrently executing two small processes at the same time. CPU intensive as in full utilizing multi cores of the system. Unlike nodejs which has asynchronous nature and single threaded and can handle IO operations more efficiently. 

In OS, we have scheduler who can manage multiple threads at the same time. it allows a thread to execute.  
NOTE: WE CANNOT CONTROL THE SCHEDULER TO SCHEDULE ONE THREAD AFTER ANOTHER. 

-- TO ASSIGN PRIORITY TO THREAD -- 
	priority range goes from 1 to 10. 1 is least priority. 10 is highest. 5 - default priority. 

	Class A extends Thread{
		public void run() {} 
	}
	
	A obj = new A()
	obj.setPriority(10) or obj.setPriority(Thread.MAX_PRIORITY) // MAX_PRIORITY - CONSTANT IN THREAD.
	obj.start()

-------------Modularity in java--------------------------------
Modularity in java provides an additional layer of encapsulation to our programs to specify which packages can be used by modules and which modules might have entry to them. 
Modules are nothing but collection of java packages & code. Modules are bought in to not increase the size of JDK as new updates come in. To avoid increasing of size of JDK, Java 9 has split the JDK into set of modules, so that we can use the required modules in our application. 
-- We also option in javac & java to specify the module path & location of the module. 

-- Module can be described using module-descriptor which is named by module-info.java. & it describes 3 things - name of module, what does the module exports & what does the module requires. 
-- Main purpose of using module is to control what we need code we need to export for the external users to use it. - can control what is visible to the outside world and what not. When we add external JAR file, we can use all the things inside it.. but we want to restrict some internal things to not be used.. to fix this, we can use Modularity. 
-- We get errors directly on compile time instead of runtime if we miss any external library.

------------------INVERSION OF CONTROL----------------------------
	Controller layer - to handle a particular route we may need to hit business layer and to get some data from the DB, from business layer, we may need to hit repository layer.. to hit another layer, we will have to make its object. 
	
	THIS CREATION OF A NEW OBJECT IS A BIG DEAL.. AS ITS NOT JUST ABOUT CREATING AN OBJECT. ITS ABOUT MANAGING ENTIRE LIFE CYCLE OF OBJECT - CREATION, DESTRUCTION
	This process of creation of new object which can be taken care by someone else.. and we just focus on the business Logic. THIS PATTERN IS CALLED AS INVERSION OF CONTROL
	
	Basically We have the control of creating our OWN OBJECT..BUT WE ARE giving the control of creating an object to someone.. SO INVERTING THE CONTROL.. INVERSION OF CONTROL. 
	
	IOC is just a principle. DEPENDENCY injection is the actual implementation of IOC. WE IMPLEMENT IOC WITH THE HELP OF DEPENDENCY INJECTION. DI is a design pattern. 


Now, If we need that particular object, We won't create the object. we will just ask Spring framework and it will inject the dependency for us. WE JUST MENTION THE REFERENCE. 

3 types to do DEPENDENCY injection: 

1. Constructor Injection - 
		
	What we do is - we make a constructor of our Controller.. and in that constructor we pass the service and assign it our controller service.. and now it will inject the object. 
	
	class Service {
		public void doSomething() {}
	}
	
	class Controller {
		private Service service;
		public Controller(Service service) {
			this.service = service
			}
		
		public void handleRequest(){
			service.doSomething() // doSomething is method of service class. 
		}
	}

2. Setter injection: we create a setter method for the injection.. we replace constructor with setterServiceInjection.
	public void setService(Service service) {
		this.service = service
	}

3. Field Injection: We achieve loose coupling using this. we just use annotation as "@Autowired" before declaring the class object.
	
	public class Injection {
		@Autowired
		private Service service
		}
